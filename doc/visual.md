# 《神谕协议 / Oracle Protocol》V2 视觉规范

## 1. Visual thesis

- Game and audience：面向普通移动端用户、无需塔罗或 AI 背景的 2–4 分钟仪式游戏。
- Emotional promise：从一圈未知牌中亲手取出一张只属于自己的神谕。
- One-sentence visual thesis：未来手抄本围成一座安静的神谕圆环，被选中的牌像圣物一样升到中央。
- Signature visual moment：玩家点中圆周的一张卡，它从群体中脱离、旋转归正、放大到中央，翻开全息特殊牌时棱镜光只照亮这一张。
- Required qualities：逐幕清楚；实体卡重量；主角牌压倒性突出。
- Avoid：长网页信息流；三张小卡并列当主视觉；轻描淡写的普通扇形。

## 2. Composition and camera

- 竖屏响应式，主验收 390×844，最低 320×568，桌面最大宽 520 px。
- 圆环阶段为正视“仪式桌面”：更大的卡背围绕屏幕中心形成正圆牌冠，牌顶朝圆心；相邻牌重叠约 36%–44%，轮廓密集但每张仍可点选。
- 中央安全区在屏幕高度 22%–74%；圆环不得与顶部工具栏和底部动作提示碰撞。
- 聚焦阶段主卡宽 `min(70vw, 258px)`，位于视觉中心；短屏不小于 180 px；剩余圆环退到背景。
- 单牌解释优先占底部 24% 高度；英文或短屏内容超出时只滚动解释区，底部主按钮保持完整可见。
- 注意路径：当前牌位 → 圆环 → 选中主卡 → 翻牌动作 → 一句解释。

## 3. Color

- Void Vellum `#090A0D` 62%；Raised Vellum `#15151A` 18%。
- Bone Ink `#EEE8D8` 主字 10%；Ash `#A9A395` 次字 4%。
- Old Gold `#C8A55B` 选择、进度、边线 4%。
- Model Cyan `#65C7C0` 仅用于拓扑和全息边 1%。
- Vermilion `#C84E3B` 仅用于逆位与错误 1%。
- 全息光谱仅在当前特殊主卡中出现；禁止整页蓝紫渐变和金色外发光。

## 4. Typography

- 中文标题：`Noto Serif SC / Songti SC / STSong`，28–38 px，700。
- 英文展示：Cormorant/Georgia，32–44 px，600。
- 正文：Inter / Noto Sans SC / 系统无衬线，16–18 px，行高 1.55。
- 仪式短标签：`ui-monospace`，10–12 px，字距 `0.12em`。
- 每屏主标题最多两行；解释最多 3 行；禁止以小字号容纳更多信息。

## 5. Shape, material, and lighting

- 主要形状：2:3 卡片、神谕圆环、断裂同心轨道、8 角星。
- 卡牌圆角 14 px；按钮 4 px；不使用胶囊与通用玻璃卡片。
- 卡牌主阴影 `0 22px 56px rgba(0,0,0,.62)`；圆环小卡阴影更轻。
- 材质：黑羊皮纸、骨白蚀刻、磨损旧金、局部棱镜箔。
- 选中牌从正圆牌冠的叠牌关系中抽离并旋转归零，形成“被命运点名”的秩序变化。

## 6. Characters, environments, and assets

- 12 张正面插画均为 1:1 精细暗底线描，不再做 2:3 `cover` 裁切。用户圈选确认的「数据集、弃用、幻觉、开源之星、提示词」作为系列参考；其余七张以这五张的共同形式重制。
- 每张图至少 75% 为 `#07090B` 至 `#15151A` 的煤黑/近黑羊皮纸；骨白、旧金、氧化铜与少量冷青只组成线刻主体。禁止白色纸张、奶油底、明亮矩形底板、画中画边框和“白图贴进黑卡”的拼贴感。
- 每张只保留一个清楚的寓言场景；统一为细窄、略带手工波动的扁平轮廓线。禁止写实手部/绳索、3D 金属、骷髅徽章、机器人角标、装饰框、径向曼陀罗与纸雕齿轮。
- 普通牌保持哑光干墨与细线刻；特殊牌可预留少量铜绿与棱镜刻线，但真正的动态全息仍由界面层完成。
- 实体牌为 2:3，内部插画窗严格 1:1；顶部 12% 用作编号铭牌，中央约 60% 为完整方图，底部约 24% 用作牌名、正逆位和白话关键词。
- 卡背中央 1:1 纹章由 Aigram transit 以 AlterU 水印 Logo 为 `ref_url` 生成；保留 Logo 两段式书写轮廓，转译为骨白压印、旧金环与冷青神经线。外层 2:3 卡框由界面统一提供。
- 主体在完整方图中可读；无文字、伪 UI 和机器人脸。
- 圆环只显示卡背；卡面插画必须等到中央翻开后出现。
- 全息层不得压过人物/符号、牌名、正逆位与焦点框。

## 7. UI and icons

- 自制 24×24 SVG 线性图标，1.5 px 骨白描边。
- 每屏只有一个旧金主按钮；次要“换一张 / 上一页”保持透明。
- 圆环卡每张拥有独立按钮语义；390 宽卡片为 94 px，320 宽为 82 px，均大于 44×44 px。
- 顶部只保留当前牌位和 `n/3`；信息与语言工具保持安静。
- Pressed：卡上移 4 px、旧金边；Focus：2 px 骨白外框；Disabled：透明度 0.4；Success：中央封印；Error：朱红短句。
- 禁止 Emoji 功能图标。

## 8. Motion and VFX

- 正圆牌冠展开以“过程”为主角：每张牌 760 ms，从中央牌堆离堆，经切线弧段、4.5% 越位再回落；卡片按 42 ms 错峰，12 张总展开约 1.22 s。
- 选择确认：先用 90 ms 沿半径向外抽出 10%，牌冠同时后退；随后经 42% 半径中点旋正、轻微越位，在 440 ms 内放大到中央。
- 抽走一张后，剩余 11/10 张重新从中央按同一细腻过程补成正圆，不瞬间跳位。
- 换牌：260 ms 回到圆周；确认翻牌 560 ms；解释淡入 260 ms。
- 圆环背景在聚焦时降到 0.16，并以 `scale(.9)` 后退，强调空间层次。
- 全息主卡光谱周期 5.2 s、常态 0.42、峰值 0.48；只动画 background-position 与 opacity。
- Reduced motion：所有位移与 3D 翻转改为 120 ms 交叉淡入，布局终态相同。

## 9. References translated into principles

- Codrops Baraja：保留显式卡序、逐牌旋转/位移/层级的核心机制；把传统展开转译为半径相等的 360° 正圆叠牌牌冠，并用 promote 逻辑将选中卡置顶。
- 传统塔罗桌面：保留一次只面对一张牌的仪式节奏；不复制水晶球、星座贴纸或确定性预言。
- CSS Holographic Masks：只给稀有中央主卡加入移动光谱；不复制原图、不使用页面固定背景。

## 10. Anti-patterns

- 禁止把三张牌、三段解释、反思问题、免责声明和重玩按钮堆成一张长网页。
- 禁止三张小卡并排承担揭示高潮；高潮必须是一张中央大卡。
- 禁止牌堆只做一次普通扇形后就退化为选择列表。
- 禁止技术黑话进入面向玩家的核心解读。
- 禁止每张牌全息、全屏霓虹、玻璃拟态、胶囊按钮、Emoji 图标。
- 禁止依赖动画完成事件解锁关键操作。

## 11. Vertical-slice acceptance

- Entry：3 秒内明白这是抽塔罗牌，不需读说明。
- Gameplay：正圆叠牌构图在 390×844 和 320×568 中完整；圆环卡片不是小图标，相邻视觉叠压达到 36%–44%；选中的牌明显离开圆环并居中放大。
- High-feedback：全息牌的中央揭示明显高于普通牌，文字仍清楚。
- Completion：过去、当下、下一步与今日提示各为独立页面，任一页不超过一个解释段。
- Narrow mobile：主按钮 ≥44 px；正文 ≥16 px；没有水平溢出和不可达操作。
- English short viewport：单牌解释和阅读正文允许内部纵向滚动；主按钮与分页导航不得随正文滚出画面。
- QA：必须包含圆环、聚焦背面、普通翻牌、全息翻牌、分页解读、最终提示在两种目标尺寸的匹配证据。
